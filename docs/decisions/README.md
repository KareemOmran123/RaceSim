# Architecture Decision Records

This directory will contain Architecture Decision Records (ADRs) for material technical choices made as RaceSim evolves. ADRs should be added when a decision affects system structure, service or data ownership, public contracts, significant dependencies, or long-term maintenance.

Use a short, numbered Markdown file for each decision, for example `0001-example-decision.md`. Each ADR should include:

## Decision

What was decided, stated clearly.

## Reason

Why the decision is appropriate in the project context.

## Alternatives

The realistic options that were considered.

## Tradeoffs

The benefits, costs, risks, and limitations accepted with the decision.

ADRs should preserve history. If a decision changes, add a new ADR and mark the earlier record as superseded rather than silently rewriting the original rationale.
